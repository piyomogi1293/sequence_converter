# Requirements: sequence-converter-core

> **作成日時**: 2025-12-13T02:04:30Z
> **プロジェクト説明**: Pythonベースのシーケンス変換ツール - 様々な形式のシーケンスデータ（配列、時系列データ、フォーマット等）を相互変換する機能を提供

---

## 概要

PNG/JPG/PDF形式のシーケンス図画像をPlantUMLテキスト形式に変換するPythonツール。

### ユーザーストーリー

シーケンス図画像を`input`フォルダに保存し、本ツールを実行すると`output`フォルダに.puml形式のファイルが保存される

## 背景・目的

このツールは、コンピュータビジョンとOCR技術を使用してシーケンス図のコンポーネントを分析し、対応するPlantUMLコードを生成することで、画像ベースのシーケンス図をLLMやテキストベースの処理に対してアクセス可能にする。

## 機能要件

### 機能要件1

- PNG/JPG形式のシーケンス図画像ファイルを入力として受け取り、処理を開始できること(`input`フォルダから読み込み)
- 画像に対して二値化およびノイズ除去などの前処理を実行し、その結果を後続の検出フェーズに渡すこと

### 機能要件2：オブジェクトヘッダー（参加者）の検出

- 画像上部からオブジェクトヘッダー（オブジェクト名を含む矩形）を検出できること
- 検出したヘッダー領域にOCRを適用し、オブジェクト名を取得できること
- 各オブジェクトの中心X座標をライフライン位置として記録し、左から右の順序を保持できること

### 機能要件3：メッセージ矢印の検出とライフラインマッピング

- 画像を上から下にスキャンし、メッセージ矢印を表す水平線セグメントを検出できること
- 水平線端点の矢印（三角形／「>」形状）からメッセージ方向を判定できること
- 検出した矢印の端点を、近傍のライフラインにマッピングし、送信元・宛先オブジェクトを特定できること

### 機能要件4：メッセージラベルの抽出と色情報の付与

- 画像全体に対してOCRを実行し、バウンディングボックス付きのテキスト領域を抽出できること
- メッセージ矢印近傍のテキストをメッセージラベルとして紐付けること
- テキストは日本語と英語に対応していること
- テキスト色（赤・青・デフォルト）を判定し、PlantUML出力に色情報を付与できること

### 機能要件5：自己呼び出し(Self_Call)の検出

- 幾何学的形状の検出により、ライフライン付近の円形状を自己呼び出しとして識別できること
- 自己呼び出しに付随するテキスト（円の右側など）を検出し、メッセージラベルとして扱えること

### 機能要件6：ノート注釈(Note_Annotation)の検出

- ライフラインと重なる／独立する矩形からノート注釈候補を検出できること
- ノート内のテキストをOCRで取得し、PlantUMLの note over [object_name] : [text] 構文として出力できること

### 機能要件7：アクティベーションバーの検出

- ライフライン近傍の垂直矩形をアクティベーションバーとして検出できること
- アクティベーションバーのY座標範囲を期間情報として管理し、その範囲内にあるメッセージをアクティベーション中のメッセージとしてマークできること
- PlantUML出力に対応するアクティベーション構文を含めること

### 機能要件8：フラグメント（alt/loop等）の検出

- 複数ライフラインに跨る大きな矩形フレーム（実線/破線）をフラグメントとして検出できること
- 左上ラベル領域からOCRにより alt、loop などのフラグメントタイプを識別し、タイトルテキストも取得できること
- ラベルがない場合は、フラグメントを一般的なグループとして処理できること

### 機能要件9：PlantUMLコードの生成

- 検出したオブジェクト、メッセージ、自己呼び出し、ノート、アクティベーション、フラグメント等をもとに、構文的に正しいPlantUMLシーケンス図コードを生成できること
- 生成したPlantUMLを標準出力へ出力できること
- 生成したPlantUMLを .puml ファイルとして保存できること(`output`フォルダへ保存する)

## 非機能要件

- エラー耐性
  - 入力ファイルが破損・非対応フォーマットの場合でも、適切なエラーメッセージを表示し、ツールが異常終了しないこと
  - オブジェクト検出やライフラインマッチングが一部失敗しても、ログに記録した上で残りの要素の処理を続行できること
- ログ出力
  - 検出失敗（オブジェクト、矢印、ノート、自己呼び出しなど）の情報をログとして記録できること
- 拡張性・保守性
  - 画像処理モジュール、OCRモジュール、PlantUML生成モジュールが分離されており、将来的なアルゴリズム差し替えが容易であること
- 利用性
  - コマンドラインからの実行を前提とし、標準入力／ファイル指定など、一般的な開発者ワークフローで利用しやすいこと

## 制約条件

- システム構成・技術的制約
  - 実装言語は Python とする
  - OCRエンジンとして Tesseract（OCR_Engine）を使用する
  - 出力形式は PlantUML シーケンス図構文（PlantUML_Output）とする
- 入出力フォーマット
  - 入力画像は PNG/JPG 形式に対応する(`input`フォルダを読み込む)
  - 出力ファイルは .puml 拡張子のテキストファイルであること(`output`フォルダに格納する)
- 画像解析上の制約（設計パラメータ）
  - メッセージ矢印のライフラインマッチングは、X座標が20ピクセル以内の最も近いライフラインにマッチングする
  - メッセージラベルの探索は、矢印のY座標から上下5〜30ピクセル範囲のテキスト領域を対象とする
  - 自己呼び出しの場合、円の中心X座標がライフライン位置の近傍であることを前提に判定する
- 出力表現の制約
  - 色付きテキストは [#red] や [#blue] などのPlantUMLの色構文で表現する
  - ノートは note over [object_name] : [text] 構文で表現する
- OCRエンジンはtesseractとEasyOCRに対応する

## 受け入れ基準

- テスト用に`input`フォルダにPNG画像`3gpp23228_fig0501.png`を、それに対応した.pumlファイルを`output`フォルダに`3gpp23228_fig0501.puml`を格納しているので、それを利用してテスト実施可能。

### 要件1（画像入力と前処理）の受け入れ基準

1. ユーザーがPNGまたはJPG画像ファイルを提供したとき、Sequence_Diagram_Converterはファイルを受け入れて処理を開始しなければならない
2. 入力ファイル形式がサポートされていないとき、Sequence_Diagram_Converterは入力を拒否して適切なエラーメッセージを表示しなければならない
3. 画像ファイルが破損しているか読み取り不可能なとき、Sequence_Diagram_Converterはエラーを適切に処理してユーザーに通知しなければならない
4. 処理が開始されたとき、Sequence_Diagram_Converterは二値化とノイズ除去を含む画像前処理を適用しなければならない
5. 前処理が完了したとき、Sequence_Diagram_Converterはオブジェクト検出フェーズに進まなければならない

### 要件2（オブジェクトヘッダー検出）の受け入れ基準

1. 画像の上部セクションをスキャンするとき、Sequence_Diagram_Converterはオブジェクト名を含む矩形を検出しなければならない
2. 矩形が検出されたとき、Sequence_Diagram_Converterは囲まれた領域を抽出してOCRを適用し、オブジェクト名を取得しなければならない
3. OCR処理が完了したとき、Sequence_Diagram_Converterは各矩形の中心X座標をライフライン位置として記録しなければならない
4. 複数のオブジェクトが検出されたとき、Sequence_Diagram_Converterはオブジェクトの左から右への順序を維持しなければならない
5. いずれかの矩形でオブジェクト検出が失敗したとき、Sequence_Diagram_Converterは失敗をログに記録し、残りのオブジェクトの処理を続行しなければならない

### 要件3（メッセージ矢印検出）の受け入れ基準

1. 画像を上から下にスキャンするとき、Sequence_Diagram_Converterはメッセージ矢印を表す水平線セグメントを検出しなければならない
2. 水平線が検出されたとき、Sequence_Diagram_Converterは端点で三角形または">"形状を識別して矢印の方向を決定しなければならない
3. 矢印の端点が識別されたとき、Sequence_Diagram_Converterは開始と終了のX座標を20ピクセルの許容範囲内で最も近いライフライン位置にマッチングしなければならない
4. ライフラインマッチングが成功したとき、Sequence_Diagram_Converterはメッセージの送信元と宛先オブジェクトを記録しなければならない
5. ライフラインマッチングが失敗したとき、Sequence_Diagram_Converterはマッチしなかった矢印をログに記録して処理を続行しなければならない

### 要件4（メッセージラベル抽出）の受け入れ基準

1. 画像全体を処理するとき、Sequence_Diagram_ConverterはOCRを使用してバウンディングボックス付きのすべてのテキスト領域を抽出しなければならない
2. 矢印が検出されたとき、Sequence_Diagram_Converterは矢印のY座標から上下5〜30ピクセル以内のテキストを検索しなければならない
3. 矢印の近くにテキストが見つかったとき、Sequence_Diagram_Converterはそのテキストをメッセージラベルとして関連付けなければならない
4. テキストの色を分析するとき、Sequence_Diagram_Converterはテキストが赤、青、またはデフォルト色であるかを判定しなければならない
5. PlantUML出力を生成するとき、Sequence_Diagram_Converterは色付きテキストに[#red]や[#blue]のような色注釈を含めなければならない

### 要件5（自己呼び出し検出）の受け入れ基準

1. 幾何学的形状をスキャンするとき、Sequence_Diagram_ConverterはHough変換または類似の技術を使用して円形状を検出しなければならない
2. 円が検出されたとき、Sequence_Diagram_Converterは円の中心X座標がライフライン位置の近くにあるかどうかをチェックしなければならない
3. 円がライフラインにマッチしたとき、Sequence_Diagram_Converterはそれを自己呼び出しとして識別しなければならない
4. 自己呼び出しを処理するとき、Sequence_Diagram_Converterは円の右側に水平方向にテキストを検索しなければならない
5. 自己呼び出しテキストが見つかったとき、Sequence_Diagram_Converterはそのテキストを自己呼び出しメッセージラベルとして使用しなければならない

### 要件6（ノート注釈検出）の受け入れ基準

1. 矩形領域をスキャンするとき、Sequence_Diagram_Converterはライフラインと重なるまたは独立している矩形を識別しなければならない
2. 潜在的なノート矩形が見つかったとき、Sequence_Diagram_Converterは重要なテキストコンテンツが含まれているかどうかをチェックしなければならない
3. テキストコンテンツが確認されたとき、Sequence_Diagram_ConverterはOCRを使用してテキストを抽出しなければならない
4. PlantUMLを生成するとき、Sequence_Diagram_Converterは"note over [object_name] : [text]"構文を使用してノートをフォーマットしなければならない
5. ノートの配置が曖昧なとき、Sequence_Diagram_Converterはノートを最も近いオブジェクトに関連付けなければならない

### 要件7（アクティベーションバー検出）の受け入れ基準

1. ライフライン領域をスキャンするとき、Sequence_Diagram_ConverterはライフラインX座標の近くにある垂直矩形を検出しなければならない
2. 垂直矩形が検出されたとき、Sequence_Diagram_ConverterはそのY座標範囲をアクティベーション期間として記録しなければならない
3. メッセージを処理するとき、Sequence_Diagram_ConverterはメッセージのY座標がアクティベーションバーの範囲内にあるかどうかをチェックしなければならない
4. メッセージがアクティベーションバーと交差するとき、Sequence_Diagram_Converterはそのメッセージをアクティベーションメッセージとしてマークしなければならない
5. PlantUMLを生成するとき、Sequence_Diagram_Converterはマークされたメッセージに適切なアクティベーション構文を含めなければならない

### 要件8（フラグメント検出）の受け入れ基準

1. 大きな矩形フレームをスキャンするとき、Sequence_Diagram_Converterは複数のライフラインにまたがる実線と破線の両方の矩形を検出しなければならない
2. フラグメント矩形が検出されたとき、Sequence_Diagram_Converterはラベル検出のために左上隅の領域を抽出しなければならない
3. ラベル領域を処理するとき、Sequence_Diagram_ConverterはOCRを使用して"alt"、"loop"などのフラグメントタイプラベルを識別しなければならない
4. ラベルが見つかったとき、Sequence_Diagram_Converterはラベルの右側にあるタイトルテキストも抽出しなければならない
5. ラベルが存在しないとき、Sequence_Diagram_Converterはフラグメントを一般的なグループ化として処理しなければならない

### 要件9（PlantUML出力）の受け入れ基準

1. すべての処理が完了したとき、Sequence_Diagram_Converterは構文的に正しいPlantUMLコードを生成しなければならない
2. コンソールに出力するとき、Sequence_Diagram_ConverterはPlantUMLテキストを標準出力に書き込まなければならない
3. ファイルに保存するとき、Sequence_Diagram_Converterは生成されたコンテンツを含む.pumlファイルを作成しなければならない
4. 色情報を含めるとき、Sequence_Diagram_Converterは適切なPlantUML色構文を使用しなければならない
5. 生成されたPlantUMLが処理されるとき、Sequence_Diagram_Converterは有効なシーケンス図を生成することを保証しなければならない
