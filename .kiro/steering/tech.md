# Tech Steering

## 技術スタック

### 言語・ランタイム

- **Python 3.x**
  - プライマリ言語として採用
  - .gitignoreから標準的なPythonプロジェクト構成を確認

### 開発ツール

- **Git**: バージョン管理
  - リポジトリ: `https://github.com/piyomogi1293/sequence_converter.git`
  - メインブランチ: `main`
  - 基本の開発用ブランチ: `dev`
- **Cursor + Claude Code / cc-sdd**
  - /kiro: 系コマンドを用いた要件定義・設計・実装支援

### 環境管理

- **uv**
  - Python 仮想環境と依存関係管理を一元管理する
  - `pyproject.toml` を単一のソース・オブ・トゥルースとし、`uv add`, `uv sync` により依存関係を管理する
  - 原則としてグローバルインストールは行わず、プロジェクトローカルの仮想環境を使用する

## コード品質・スタイル

### フォーマッタ / Linter

- **black**
  - 標準コードフォーマッタとして採用
  - すべての Python ファイルを black で自動整形する
- **isort**
  - import 文の順序とグルーピングを統一
  - black と競合しない設定（`profile = "black"` 等）を採用する
- **flake8**
  - 静的解析ツールとして採用
  - 最低限のルール（未使用変数、未使用 import、循環 import 等）から開始し、必要に応じてプラグイン／ルールを拡張する
- **pre-commit**
  - コミット前フックで以下を自動実行する:
    - black による整形
    - isort による import 整理
    - flake8 による静的解析
  - 原則として `pre-commit` を有効化した状態でのみ PR を作成する

### コード規約

- スタイル:
  - PEP8 をベースとしつつ、black/isort/flake8 のルールを実質的な規約とする
  - 手動での整形は最小限とし、「ツールの結果に合わせる」方針を取る
- 型:
  - 可能な限り型ヒント（type hints）を付与する
  - 将来的に mypy 等の型チェッカー導入を想定した記述を心がける

## 依存関係管理

- 管理方針:
  - すべての依存関係は `pyproject.toml` に定義する
  - 本番用依存関係と開発用依存関係を分離する（例: `[project]` と `[dependency-groups.dev]`）
- 追加手順:
  - 本番用ライブラリ: `uv add ライブラリ名`
  - 開発用ライブラリ: `uv add --group dev ライブラリ名`
- ロックファイル:
  - `uv lock` によりロックファイルを管理し、CI・本番環境でも同一バージョンを再現する

## テスト戦略

- テストフレームワーク:
  - pytest を採用
  - ユニットテストを最小単位としつつ、画像認識・OCR 部分についてはサンプル画像を用意した統合テストも検討する
- 実行:
  - `uv run pytest` のように uv 経由で実行することを基本とする
